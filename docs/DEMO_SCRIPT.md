# Demo recording brief

**English** · [Türkçe](DEMO_SCRIPT.tr.md) · [Documentation](INDEX.md)

Status: script ready; video **not recorded**. Never use generated UI previews as
evidence of a live model run. Record after the live memory/voice acceptance checks pass.

## Before recording

- Use a separate test data directory, not your personal history or memory.
- Use [project-brief.md](demo/project-brief.md); close notifications and private windows.
- Keep the selected LLM local; start with web/cloud speech disabled.
- Note the Windows/Python/model/voice versions and hardware privately for the caption.
- Confirm candidate extraction and approved-memory recall work in that exact configuration.
- Use only your own voice or a permitted preset; obtain consent for anyone else recorded.

## 60–90 second storyboard

| Approximate segment | Screen action | Narration idea |
| --- | --- | --- |
| 0–10 s | Open with Alt+Space; show selected local model | “A desktop assistant for the local model you choose.” / “Seçtiğin yerel model için masaüstü asistanı.” |
| 10–35 s | Import synthetic brief, enable document context, ask for priorities | Show the answer and where it came from; keep factual content readable |
| 35–50 s | Enable local speech for one short paragraph | Let viewers hear the actual output; disclose if generation pauses were cut |
| 50–75 s | State a durable preference, open candidates, inspect and approve it | “Memory is reviewable, not hidden.” / “Hafıza senin kontrolünde.” |
| 75–90 s | New conversation, verified recall; show limitations and repository end card | “Development preview. Windows. Local models. Contributions welcome.” |

These times are an editing target, not latency promises. If extraction takes longer,
use a clearly labelled cut or make a longer demo; never simulate successful recall.
If automatic extraction fails, fix it before filming that segment. An explicit
`/remember` demonstration is acceptable only if labelled as explicit saving.
